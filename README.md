# 日镜账

中文名：**日镜账** · 前缀 `daysnap` · 端口 **6600 / 11600**

## 骨架

**日终余额抽取 → 周期快照落行 → 变动流水回放核对 → 断档/跳变检出 → 快照与回放差额清单**

皮：收单/结算账户的日终余额镜。去皮是 **周期快照事实 + 流水回放守恒 + 断档跳变检出**，不是银行核心 CRUD、不是日结封账锁定、不是双边齐账。

## 已落地：半截抽取回滚（补偿悬挂口径）

全局唯一架构，与「整票回滚」二选一，本库贯彻**补偿悬挂**：

- 抽取任一户写入抛错 → 本批已写户快照置「悬挂」并挂失败批号（`悬挂镜` 表登记失败前原貌），`抽取批次.状态='失败'` 可查；绝不留下「批失败但部分户持本批有效镜」。
- 未跑补偿（`POST /api/补偿`）前，该营业日回放**整票拒绝（409）**；悬挂镜状态非有效，快照/差额发布口径读不到它。
- 补偿整票清理（新插镜撤销、盖写镜恢复旧余额旧批号）→ 核证 `valid=true`、可回放、可重抽。
- 同营业日在途闸（`抽取闸` 表）+ 悬挂未补偿拒抽，失败与同日重抽交错时双批有效镜永不并存。
- 核证接口 `GET /api/核证?营业日=...`：批号、悬挂户、在途批、可否回放、valid。
- 失败注入：`POST /api/失败注入`（按账户键或扫描序第 N 户，单次生效）；夹具 `fixtures/半截抽取失败样例.json`、`fixtures/同日重抽并发样例.json`。
- 自动化：`cd backend && pip install -r requirements-dev.txt && pytest`（断言残留镜与回放可否）。

## 已落地：抽取命运账 · 二次同日抽取写闸（命运前置拒绝口径）

本库在两条正向路径中择定并贯彻 **命运前置拒绝**（与「命运补偿票」口径互斥）：

- 首次抽取落成（成功或失败）与命运行**同票**写入 `抽取命运账表`：营业日、批号、成败、有效镜指纹（`账户键|余额|抽取批次` + 批号 的 SHA256）。**成功回执绝不允许命运空号**。
- 同日再抽先消化命运账：
  - **缺命运但已有有效镜**（含「抽成后抹掉命运再抽」）→ 整票拒绝（409），有效镜余额/批号/状态一律不动；
  - 有效命运=失败 → 整票拒绝（失败批命运在册时再抽必拒）；
  - 有效命运=成功 → 按台参口径重抽，重抽重钉命运、旧命运降为历史；
  - 有效命运=已补偿 → 该日已整票清理，可重新首抽。
- 命运按营业日精确取用，**邻日命运绝不串用**；同一营业日「至多一条有效命运」由部分唯一索引在库层兜底。
- 命运写、抽写、回放、差额同票：登记命运不单独提交，随调用方事务一并落库；回放只认「有效命运=成功且有效镜指纹相符」的营业日（空号/失败/指纹不符皆整票拒绝）。
- 抽写与命运补登交错**失败闭**：二者均 `BEGIN IMMEDIATE` 串行；补登见在途批/待补偿悬挂/已有命运即拒绝。修复空号走 `POST /api/命运补登`（只补「有镜无命运」，按现镜现算指纹）。
- 只读核证接口 `GET /api/核证/抽取命运?营业日=...&批号=...`：日、批号、命运、指纹、valid（valid＝唯一有效命运为成功且指纹相符）。
- 夹具 `fixtures/删命运再抽样例.json`、`fixtures/命运抢锁并发样例.json`；抽取页、回放页、抽取命运页均按日展示命运行与命运闸拦截原因。
- 自动化：`pytest` 共 22 项，含「删命运再抽整拒且镜不变」「失败命运在册再抽必拒」「邻日不串用」「抽写抢锁失败闭」「命运闸接入回放」。
